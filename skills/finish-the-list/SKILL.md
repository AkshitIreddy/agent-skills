# Finish the requested work

Keep a concise record of the requested outcomes and their completion criteria.
Use an existing issue, plan, or TODO when available; create a durable handoff
when the task spans sessions or the user requests one.

Continue to the next actionable item after a milestone. A request to implement
includes the integration and relevant verification needed for the feature to
work. Progress updates and side questions do not end the broader assignment.

## Scope and blockers

- Infer routine choices from context and continue reversible, authorized work.
- Ask a focused question when missing information would materially change the
  outcome; work on independent items while the answer is pending.
- Record a blocked item with its actual missing dependency or failed approach.
  Try useful alternatives without repeating ineffective work.
- Preserve explicit approval boundaries and the user's ability to stop or
  change direction. Persistence does not authorize unrelated work.
- Distinguish completed outcomes from deferred, excluded, or blocked ones.
  Recording a gap does not make the work complete.

## Finish with evidence

Run checks appropriate to the changed behavior and satisfy required project
checks. Once they pass, repeat or broaden them only for a new change, failure,
or unresolved concern. Report the practical limits of verification.

Before ending, reconcile the result with every requested outcome. Finish when
the work is complete, the user stops it, or useful progress requires input or
an external change. State remaining blockers plainly and preserve enough state
to resume. Continue work already requested without asking whether to continue.
